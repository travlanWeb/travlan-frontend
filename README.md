# 트래블랜 (Travlan)

🔗 **배포 링크**: https://travlan-frontend-ten.vercel.app/

Travel + Plan. 예산 기반 국내 여행 플래너 서비스입니다. 지도에서 여행지를 필터링해 **여행가방**에 담고, **타임라인**으로 세부 일정을 구성할 수 있습니다.

현대오토에버 모빌리티 SW스쿨 2차 팀 프로젝트로 제작되었습니다.

## 주요 기능

- 홈 / 지도 / 타임라인 / 커뮤니티 / 마이페이지 / 로그인 / 회원가입
- 지도 기반 장소 탐색 및 카테고리 필터링, 지도 뷰포트 기반 목록 필터링
- 여행 생성: 여행 정보(이름/기간/예산) 입력 → 장소 담기(여행가방) → 타임라인에서 일정(day/비용/순서/시간) 구성 → 저장
- 일반 로그인 / 구글 로그인(Google Identity Services)
- 커뮤니티에서 다른 사용자의 여행 둘러보기, 찜하기, 리믹스(복사해서 내 여행으로 저장)

## 기술 스택

- **Frontend**: React 19, TypeScript, Vite 7, Tailwind CSS v4
- **상태관리**: Zustand(여행가방, 여행 초안 등) + Redux Toolkit(인증, 타임라인 일정) 혼용
- **라우팅**: react-router-dom v6.4+ (`createBrowserRouter`, `useBlocker`로 이탈 가드)
- **HTTP**: axios (요청 인터셉터로 accessToken 자동 첨부, 401 시 자동 재발급/재시도)
- **지도**: react-kakao-maps-sdk (카카오맵)
- **아키텍처**: FSD(Feature-Sliced Design) 기반 `app → pages → widgets → features → entities → shared`
- **백엔드**: Spring Boot, DB는 Supabase(Postgres)
- **배포**: Vercel(프론트), AWS EC2(백엔드)

## 프론트엔드 개발 상세

- **지도 기반 장소 탐색**: 카카오맵 위에 카테고리·가격 필터가 적용된 장소를 마커로 표시하고, 지도 뷰포트(bounds) 안에 보이는 장소만 옆 목록에 실시간으로 동기화
- **여행 생성 플로우**: 지도 페이지(장소 선택) ↔ 타임라인 페이지(일정 구성)를 자유롭게 왕복하며 작성 — 두 페이지가 Zustand/Redux 전역 상태를 공유해 데이터 유실 없이 이동 가능
- **커뮤니티 리믹스**: 다른 사용자의 여행을 찜하거나, 복사해서 내 여행가방·타임라인에 그대로 불러와 수정할 수 있는 구조
- **인증**: JWT accessToken/refreshToken 기반, axios 인터셉터에서 만료 시 자동 재발급

## 트러블슈팅

**1. 이중 상태관리(Zustand + Redux) 동기화 불일치로 인한 유령 데이터**
여행가방(Zustand)에서 장소를 뺄 때 타임라인의 일정(Redux)이 같이 삭제되지 않아, 삭제된 장소의 금액·순번이 계속 남아있는 문제가 있었습니다. 장소 제거 시 관련 일정도 함께 정리하는 리듀서(`removeVisitsByPlaceId`)를 추가하고, 모든 "빼기" 진입점(사이드바, 장소 카드)에서 동일하게 호출하도록 통일해 해결했습니다.

**2. 지도 ↔ 타임라인 왕복 시 미저장 데이터 덮어쓰기**
편집 페이지가 재마운트될 때마다 서버에서 여행 데이터를 다시 불러오면서, 로컬에서 아직 저장하지 않은 변경사항(날짜, 대표사진 등)을 서버의 이전 값으로 덮어쓰는 문제가 있었습니다. 같은 여행을 이미 불러온 적 있으면 재조회를 건너뛰도록 `ref` 기반 가드를 추가해 해결했습니다.

**3. 페이지 이탈 시 미저장 변경사항 유실**
여행 작성 중 다른 페이지로 이동해도 경고 없이 데이터가 사라지는 문제가 있었습니다. React Router의 `useBlocker`로 실제 라우트 이동 시점을 가로채, 저장하지 않은 변경사항이 있을 때만 확인 창을 띄우도록 개선했습니다.

**4. 초기 로딩 성능 저하**
카카오맵 SDK를 앱 진입 시점에 전역으로 로드하고 있어, 지도를 쓰지 않는 페이지까지 로딩이 느려지는 문제가 있었습니다. 라우트 단위 코드 스플리팅(`React.lazy` + `Suspense`)을 적용하고, SDK 로더를 지도를 실제로 사용하는 컴포넌트로 이동시켜 초기 로딩 속도를 개선했습니다.

**5. Vercel 배포 후 새로고침 시 404**
정적 호스팅 환경에서 클라이언트 사이드 라우트(`/mypage` 등)로 직접 진입하면 404가 발생하는 문제가 있었습니다. `vercel.json`에 SPA 라우팅용 rewrite 규칙을 추가해 해결했습니다.

**6. 대표 사진 업로드 실패**
S3 업로드 용량 제한(10MB)을 초과한 이미지가 조용히 실패하는 문제가 있었습니다. 업로드 전 클라이언트에서 파일 용량을 검사해 초과 시 안내 문구를 표시하도록 개선했습니다.

## 시작하기

```bash
npm install
npm run dev       # 개발 서버 실행 (http://localhost:5173)
```
